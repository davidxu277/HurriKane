# 模型改进实验（交叉验证）

看过留出集后，我们检查了三个可能的技术原因：目标没对准最终距离、特征太少、没有调参。

- 数据：训练集和验证集中有后续消息的 7,557 个事件，501 个最终 Critical。留出集没有使用。
- 方法：5 折交叉验证，所有方案的误报数都对齐到基线的 108 个。
- 事先定的标准：比基线多抓至少 5% 的 Critical（至少 427 个），且各折方向一致。

| 方案 | 抓到 Critical | 比基线多 | 各折差值 |
| --- | ---: | ---: | --- |
| 基线（当前等级） | 406 | - | - |
| 当前特征，分类器 | 412 | +1.5% | 3, 2, 1, 0, 0 |
| 112 个特征，分类器 | 416 | +2.5% | 3, 1, -1, 0, 1 |
| 预测最终距离 | 411 | +1.2% | 5, -1, 3, -1, -2 |
| 112 个特征，分类器加距离 | 417 | +2.7% | 5, -1, 1, 0, 2 |
| 调参后最好（深度 4，加距离） | 418 | +3.0% | 5, -1, 2, 0, 2 |

调参共比较了 7 组参数，每组有加距离和不加两种版本，所以 +3.0% 还是从多个结果里挑出来的最好值。

结论：没有方案达到标准，模型保持 D + 时间规则不变，也不需要第二次查看留出集。在这份数据上，这三点不是模型打不过当前等级的主要原因。

复现：在项目根目录运行 `experiments/cv_experiment.py` 和 `experiments/cv_tuning.py`。
